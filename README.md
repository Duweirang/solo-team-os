## 为什么做 Solo-Team OS？

多智能体协作常见的挑战包括上下文互相影响、工具权限过宽、任务循环导致成本失控。Solo-Team OS 正在探索一种方式：像设计团队分工一样配置 Agent，并明确它们各自能看什么、能做什么、能调度谁。

## 核心理念：认知权限隔离

- **工具权**：限制 Agent 可调用的工具与操作范围。
- **调度权**：限制 Agent 可以委派任务的对象与范围。
- **认知权**：限制 Agent 可见的信息，减少不必要的上下文泄漏。

例如，盲审 Agent 只读取作品正文，不读取大纲和讨论记录，从而尝试获得更独立的读者反馈。这是设计目标与验证场景，不构成效果保证。
